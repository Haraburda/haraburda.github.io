Think of geospatial plots as standard maps that went to grad school. Instead of just showing you where a city or river sits, these plots treat locations like nodes and connections like edges, tying everything to real-world coordinates on Earth. By blending traditional graph databases with spatial data, we get to see how our data behaves in its natural habitat. It goes way beyond a basic map, adding context to help us spot deep trends and make much smarter decisions.

To help us visualize all this, we rely on a trusty lineup of visual tools. Cartograms act like a fun-house mirror, warping geographic sizes based on data instead of actual land mass. Choropleth maps take a classic color-coded approach, using shades to show data concentration. Density maps are perfect for pinpointing exactly where data points are tightly packed, while flow maps create visual networks showing how things move from Point A to Point B. We will break down each of these plots using the exact same geospatial data from our comparison graphs table.

For the heavy lifting, we bring out the big guns like ArcGIS and AutoCAD Map 3D. These software powerhouses use thousands of geoprocessing tools to reveal hidden patterns you’d normally miss, like predicting crime hotspots or finding the absolute perfect location to open a new business. Plus, they let us build interactive 2D maps and immersive 3D scenes, making complex datasets look downright beautiful. We are going to dive into each of these graphs below, using the exact same dataset from Table 1 to show you how these elements interact.

But before our grad-school maps can run any of these sophisticated models, they require a strict data passport: Federal Information Processing Series numbers, or FIPS codes. If geospatial plots are maps with advanced degrees, FIPS codes are their standardized student ID numbers. While humans prefer reading county names, mapping software is notoriously terrible at reading handwriting or interpreting local geography. To a computer, text is messy. If your dataset spells a location as "LaPorte," but your base map labels it "La Porte," or if your script encounters "Washington County" and has to guess which of the 31 different Washington Counties in the United States you actually mean, the entire visualization breaks down.

FIPS codes solve this identity crisis by replacing ambiguous text with a unique five-digit numeric fingerprint. The first two digits lock in the state, and the final three pinpoint the exact county. By stripping away text spelling variations and duplicate names, these numbers give software like ArcGIS a flawless, universal anchor to join tabular spreadsheet records directly to real-world boundary shapes. Without them, your data remains stuck in a spreadsheet, completely blind to its own geography. To ensure your script maps everything flawlessly without any regional identity crises, Table 2 lists the specific FIPS codes for the 13 counties in the LaPorte district for Indiana.

Cartogram

Think of a this as a map that values data over geography. It swaps out actual land borders for geometric shapes like circles or squares, scaling their sizes to match the data numbers rather than the actual physical dimensions. Take a look at Figure 1, which uses circles to represent the total counts across the INDOT LaPorte district. While the circle sizes might play a bit of a trick on your eyes by looking pretty uniform, the sneaky-smart color shading tells the real story. The darker gray hues over Jasper, Marshall, and Starke Counties instantly signal that these three areas are pulling in the heaviest numbers.

Choropleth

This map is essentially a high-level game of color-coding for boundaries like countries, states, or counties. Instead of guessing the metrics, the map uses specific colors, shades, or patterns to tell you exactly who is winning the data race. Zooming into the LaPorte district in Figure 2, Jasper, Marshall, and Starke counties proudly wear the darkest shade of gray, making it obvious they hold the top slots. Meanwhile, Carroll County stands out by fading into pure white, which is just our map’s polite way of saying, "Data missing, please try again later".

Density Map

Think of this map as a visual radar for crowds. It uses dots that dynamically shift in size and color to show exactly where the data is throwing a party and where things are quiet. Figure 3 is essentially a clever mashup, a "remix" if you will, of our friends the cartogram and the choropleth. It takes the best of both worlds to deliver the exact same information for our three items, just wearing two different outfits so you can appreciate the data from every angle.

Flow Map

If you have ever wondered how data actually gets around, this map is your answer. It maps out movement and quantity across different locations, using handy arrows to show you exactly which way the traffic is heading. To make things even clearer, the lines get thicker when there is a serious crowd moving along that path. Take a look at Figure 4: the whole journey kicks off in Newton and wraps up over in Carroll County, with a very busy, high-traffic connection lighting up between Marshall and White Counties along the way.

R Script Execution & Plot Generation Architecture

The following optimized ggplot2 framework generates a clean, warning-free flow map by explicitly mapping data point variables, standardizing linear tracking scales up to a 400-count threshold ceiling, and purging default chart grid lines to maximize executive clarity.

# Fix Core Centroids Coordinates (Projected EPSG: 2967) centroids_geo <- district_shapes_projected %>% st_geometry() %>% st_point_on_surface() # Keeping coordinates in projected layout coord_matrix <- st_coordinates(centroids_geo) centroids <- data.frame( FIPS = district_shapes_projected$FIPS, County = district_shapes_projected$NAME, long = coord_matrix[, "X"], lat = coord_matrix[, "Y"] ) centroids$County <- tools::toTitleCase(centroids$County) # Use centroids2 for Sequenced Flows Sort df4 by numeric sequence df4_sorted <- df4 %>% mutate(County = case_when(County == "Laporte" ~ "LaPorte", .default = County)) %>% mutate(Order = coalesce(Order, 13)) %>% arrange(Order) centroids2 <- centroids centroids2 <- centroids2[match(df4_sorted$County, centroids2$County), ] # Inject your flow data attributes centroids2$flow_ab <- df4_sorted$Count centroids2$flow_ba <- 0 centroids2 <- centroids2 %>% rename("xa" = "long", "ya" = "lat", "id_a" = "County") # Create sequential destinations ("b") matching the temporal flow sequence centroids2$xb <- c(centroids2$xa[-1], centroids2$xa[1]) centroids2$yb <- c(centroids2$ya[-1], centroids2$ya[1]) centroids2$id_b <- c(centroids2$id_a[-1], centroids2$id_a[1]) df_flow <- head(centroids2, -1) # Create Flow Lines with Matching CRS sf_flow <- flowmap_sf(flowdat = df_flow, edge_width_factor = 1, edge_offset_factor = 1, arrow_point_angle = 30, crs = 2967) plot4 <- ggplot() + geom_sf(data = countyMap, fill = "white", color = "#495057", linewidth = 0.3) + geom_sf(data = sf_flow$edges, aes(fill = flow), color = NA, alpha = 0.6) + geom_text(data = centroids, aes(x = long, y = lat, label = County), size = 3.5, fontface = "bold", inherit.aes = FALSE) + scale_fill_gradient(low = "#cccccc", high = "#3b444b") + coord_sf(expand = TRUE, default_crs = sf::st_crs(2967)) + theme_void() + theme(legend.position = "none") plot4
